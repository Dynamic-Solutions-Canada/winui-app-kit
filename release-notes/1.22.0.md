- Exiting through `HostWindow.Exit` now closes the settings windows and shuts the app down the way WinUI expects (`Application.Exit`), instead of ending the process outright. That is required for Windows App SDK 2, which crashes on every exit on Windows 10 when a running app is ended outright. Nothing changes in your exit steps; `Exit` now returns while the app closes, so keep all teardown in exit steps. If shutting down takes more than 5 seconds, the app is ended anyway and the log says so.
- New `SingleInstance.ExitThisLaunch()` ends a second launch safely. Replace the `Environment.Exit(0)` that follows a failed `SingleInstance.TryClaim` (or `ClaimSingleInstance`) with it: wsl-monitor `App.xaml.cs:48`, hub-display-switch `App.xaml.cs:51` (drop the `return;` after it), immich-drive `App.xaml.cs:90`, repilot `App.xaml.cs:51` and little-launcher `App.xaml.cs:62`.
- Little Launcher, which exits through its own code: close every window it keeps open before `Application.Current.Exit()`, because WinUI's shutdown stalls while a window is open.
- The README now notes that only Windows 10 refuses a tray icon's GUID after an update; Windows 11 keeps it.
