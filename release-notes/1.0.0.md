- First tagged release. Pin this tag instead of a bare commit; later releases follow SemVer, so only a major version breaks your app.
- Covers everything apps on the kit already use: tray icon and menu, tray flyout, window chrome and placement, the JSON settings store, start with Windows with its status, theme switching, localization (`UiText`, `Localize`, `LocalizedMessage`) and app environment helpers.
- Runs on Windows 10 22H2 (build 19045) and later, so an app that supports Windows 10 can use all of it. On Windows 10 the tray flyout has square corners; the README's "Windows 10" section lists the differences. Your app's own minimum is unchanged.
- The kit is now MIT licensed (copyright Dynamic Solutions), so you can use it in any app.
- The settings store can now version your settings file: pass your migrations and it upgrades older files after backing them up, keeps an unreadable file as `.bad`, and tells first run, migration, an unreadable file and a reset apart. `Reset()` gives you a "Reset settings" action. Existing calls behave as before.
- New `ProtectedStore` keeps credentials out of `settings.json`, encrypted to the Windows user. Pass your existing folder, file-name pattern and entropy to keep reading files you already have.
- The README has a new "Gotchas" section: behaviour your app relies on, such as identity values that must never change, flyout lifetime and language resolution. Link to it from your app's docs instead of keeping your own copy.
- New shared build configuration in `build/`: import it from your `Directory.Build.props`, `Directory.Build.targets` and `Directory.Packages.props` to get the family's build settings, the .NET security floors, the shared package versions (this moves NLog to 6.2.2 where it was older) and the shared NLog config. The README's "Shared build configuration" section lists the edits; call `AppLogging.UseDataFolder` at startup when you switch to the shared NLog config.
- The repo now carries the family's canonical `.editorconfig`. Copy it into your app unchanged; with the analyzers on, expect missing-brace warnings in existing code until you add them.
- The kit now treats its own warnings as errors in Release builds, including your app's Release build of it. On Windows 11 the API and behaviour are unchanged from the commit apps pin today.
